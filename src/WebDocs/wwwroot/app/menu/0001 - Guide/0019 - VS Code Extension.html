VS Code Extension

The Drapo extension gives Visual Studio Code first-class support for d-* markup: problems are underlined as you type, attribute names complete, hovering shows the documentation, and function calls inside d-on-* handlers get signature help. It is powered by a language server that runs the very same engine catalog and validator that power this documentation site and its MCP validate_drapo tool, so what the editor flags is exactly what the documentation would flag. There is one validator, not two.

Install

Download the .vsix package for your platform from the GitHub Releases page of the spadrapo/docs repository (releases are tagged lsp-v<version>) and install it from a terminal:

code --install-extension vscode-drapo-win32-x64-0.1.0.vsix

Or inside VS Code: Extensions view → … menu → Install from VSIX…. Each package bundles a self-contained language server, so no .NET runtime or SDK is required on the machine.

The extension activates for html, razor and aspnetcorerazor (.cshtml) files. Open one and the features are available immediately; nothing needs to be configured.

What you get

  • Diagnostics in the editor and the Problems panel (source drapo), updated within a moment of each edit:
    • unknown-attribute — a d-* attribute the engine does not define.
    • unknown-function — a function used in a d-on-* handler the engine does not dispatch.
    • wrong-arity — a documented function called with fewer arguments than it requires (warning).
    • malformed-dfor — a d-for value that is not {item} in {iterator}.
    • unbalanced-mustache — an unmatched {{ or }}.
  • Completion — type d- inside a tag to list every attribute the engine recognises, with its documentation. Prefix families such as d-on-, d-attr-, d-validation- and d-dataproperty- are offered as prefixes so you can continue with the suffix.
  • Hover — hover a d-* attribute for its description, or a function name inside a d-on-* value for its signature, description and parameter table.
  • Signature help — inside the parentheses of a handler call (for example after typing UpdateSector() the parameter list appears with the current parameter highlighted; a comma advances it.

Example: the line below produces an unknown-attribute error on d-nope and a wrong-arity warning on the call, because UpdateSector requires at least two arguments.

<div d-nope="x"></div>
<button d-on-click="UpdateSector()">Go</button>

Settings and commands

SettingDefaultDescription
drapo.server.pathemptyAbsolute path to a Drapo.LanguageServer executable. Leave empty to use the server bundled with the extension. Useful for development or for a platform without a bundled build.
drapo.trace.serveroffmessages or verbose writes the client/server protocol to the Drapo Language Server output channel.

Command palette: Drapo: Restart Language Server. If the server cannot be found or fails to start, the extension shows an error notification naming the cause instead of failing silently.

How it works

The docs repository contains a class library, Drapo.Tooling, that reads the attribute and function sets from the bundled drapo.js engine and the function signatures from this documentation. The website, the MCP server and the language server all use that one library, so the three can never disagree. Documentation content is copied into the extension at build time; the extension works offline and does not contact this site. When the documentation or the engine version changes, a new release of the extension picks it up.

AI coding assistants benefit as well. Agents such as GitHub Copilot agent mode and the Claude Code IDE extension read the editor's diagnostics, so a bad d-* edit is fed back to them without calling the MCP.

Other editors

The server speaks the standard Language Server Protocol over stdin/stdout, so any LSP-capable editor (Neovim, Sublime Text, Emacs, Visual Studio's LSP client, and others) can use it. Take the Drapo.LanguageServer executable from a VSIX package (it is a zip; the binary sits under extension/server/<platform>/) or build it from source, and point your editor's LSP client at it for html, razor and aspnetcorerazor documents.

# from a clone of spadrapo/docs, run against the live documentation content
dotnet run --project src/Drapo.LanguageServer -- --content src/WebDocs/wwwroot/app

# print the server and engine version
Drapo.LanguageServer --version

Building from source

Prerequisites: .NET SDK 8 and Node.js 20+. From a clone of the repository:

cd src/Drapo.LanguageServer
./publish.ps1 -Rid win-x64            # self-contained server (also linux-x64, osx-x64, osx-arm64)
cd ../vscode-drapo
npm ci
./scripts/copy-server.ps1 -Rid win-x64
npm run package:win32-x64             # produces vscode-drapo-win32-x64-<version>.vsix
code --install-extension vscode-drapo-win32-x64-0.1.0.vsix

To debug the extension, open src/vscode-drapo in VS Code, press F5, and in the development host set drapo.server.path to the Debug build of the server. npm test runs an integration test in a real VS Code instance; dotnet test src/docs.sln runs the tooling and server tests, including a parity corpus that checks every documented function sample.

Releasing (maintainers)

In the repository go to Actions → Release extension → Run workflow and optionally type the version (for example 0.2.0). The workflow bumps src/vscode-drapo/package.json if needed, creates the lsp-v<version> tag and starts the CI build, which tests everything, packages the four platform VSIX files and attaches them to a GitHub Release named after the tag.

The same can be done by hand: bump the version, then push the tag.

git tag lsp-v0.2.0
git push origin lsp-v0.2.0

Current limits

  • Knowledge is framework-level: the engine's attributes and functions and their documented signatures. Symbols your application defines (d-dataKey names, sectors, components) are not resolved yet; use the Drapo Resolver Skill for that.
  • Validation is the same text-based check the documentation validator performs; it does not parse expressions.
  • Packages are distributed through GitHub Releases; the extension is not on the Marketplace yet.
